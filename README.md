# Airfoil Noise Predictor

Single-page Streamlit application that estimates the **scaled sound pressure level (dB)** of airfoil self-noise from five wind-tunnel test inputs, trained on the UCI Airfoil Self-Noise dataset (NASA wind tunnel experiment).

## 1. Project overview

The goal is a Release 1.0 baseline ML regression app: given five measured airfoil test conditions, predict the scaled sound pressure level in dB. The backend is a frozen scikit-learn pipeline (Experiment B feature representation + SVR with RBF kernel). The frontend is one Streamlit page with five bounded `number_input` fields, one Predict button, and one 2-decimal dB result. No user accounts, no history, no file upload, no REST API, no database, no cloud components.

## 2. Scientific problem statement

Airfoil self-noise is broadband noise generated by turbulent boundary-layer interaction with the airfoil trailing edge. Given a set of wind-tunnel test conditions — frequency, angle of attack, chord length, free-stream velocity, and suction-side displacement thickness — estimate the resulting scaled sound pressure level. This is a supervised regression problem on a fixed experimental dataset: no live sensing, no retraining in production, and predictions are valid only inside the observed operating envelope.

### Dataset description and five input variables

| Variable | Unit | Observed range (bounds enforced in app) |
|---|---|---|
| `frequency_hz` | Hz | 200.0 – 20,000.0 |
| `angle_of_attack_deg` | degrees | 0.0 – 22.2 |
| `chord_length_m` | m | 0.0254 – 0.3048 |
| `free_stream_velocity_m_s` | m/s | 31.7 – 71.3 |
| `suction_side_displacement_thickness_m` | m | 0.000400682 – 0.0584113 |

Target: `scaled_sound_pressure_level_db` (dB), range 103.38 – 140.987 dB (mean 124.84). All 1,503 rows are numeric, non-finite-free, duplicate-free, and no missing values (validated by `src/airfoil_noise/validation.py`; covered by `tests/test_data.py` and `tests/test_validation.py`).

Note from UCI metadata: the attack-angle column is labelled "Binary" but the file contains 27 distinct numeric values; it is treated as numeric and the discrepancy is documented.

## 4. Methodology

1. **Ingestion and validation** — `src/airfoil_noise/data.py` loads the raw `.dat`; `src/airfoil_noise/validation.py` checks schema, row count (1,503), dtypes, missing values, finiteness, duplicates, and input bounds.
2. **Operating groups** — groups are defined by the four experimental-condition columns (`angle_of_attack_deg`, `chord_length_m`, `free_stream_velocity_m_s`, `suction_side_displacement_thickness_m`); `frequency_hz` is excluded so every frequency variant of one condition shares a group. Exactly 106 groups.
3. **Group-aware split** — `GroupShuffleSplit(test_size=0.20, random_state=42)` over groups: 84 training groups (1,188 observations) and 22 holdout groups (315 observations). Disjoint group sets, no frequency-based leakage.
4. **Feature experiments** — two exactly-five-feature representations:
   - **Experiment A:** the five original inputs.
   - **Experiment B:** `frequency_hz` replaced by `log10_frequency_hz`; the other four features unchanged.
5. **Model comparison** — five candidates (Linear Regression, Ridge, Random Forest, SVR RBF, Gradient Boosting) tuned with GridSearchCV inside GroupKFold(5) on training groups only; selection metric = lowest mean GroupKFold CV MAE. Experiment B + SVR wins (CV MAE 1.8947 vs 2.3147 for Experiment A SVR; see `reports/model_comparison.csv`).
6. **Frozen artifact** — `src/airfoil_noise/artifact.py` refits the winning pipeline on all 1,188 training observations, stages to `models/*.tmp`, verifies in a fresh Python process (finite, matches in-memory pipeline on a real dataset row), then promotes to `models/best_model.joblib` + `models/model_metadata.json`. The pipeline accepts the five raw inputs; `log10(frequency_hz)` is computed inside it.
7. **Holdout evaluation** — one shot, no retuning: holdout MAE 2.0673 dB, RMSE 3.1444 dB, R² 0.7702 on 315 observations (`reports/holdout_evaluation.json`, `reports/holdout_predictions.csv`).
8. **Explainability** — permutation importance on holdout (`n_repeats=30`, `random_state=42`), residual-by-frequency scatter, residuals per holdout group (`reports/residual_analysis.md`).

## 5. EDA findings

(from `reports/feature_variant_analysis.md`, measured on the validated processed dataset)

- `frequency_hz` is strongly right-skewed (skewness +2.1371; median 1,600 Hz against a 200–20,000 Hz range). `log10` compression brings skewness to approximately zero (−0.0318) with 21 distinct values preserved in both representations.
- Pearson correlation with the target: raw frequency −0.3907 vs `log10_frequency_hz` −0.3547. Weaker linear correlation under the log transform does not imply worse predictive performance — Pearson measures linear association only; model performance is assessed on held-out data.
- Other target correlations (identical in both experiments): angle of attack −0.1561, chord length −0.2362, free-stream velocity +0.1251, thickness −0.3127.

## 6. Feature transformation experiments

**Experiment B (`log10_frequency_hz` + four unchanged inputs)** was selected because it yielded the lowest mean GroupKFold CV MAE across all ten variant/model combinations. The log10 transform lives inside the fitted pipeline, so the app and backend always consume the raw five features in documented order.

## 7. Group-aware validation methodology

Group ids are computed once from the four-condition key (`pd.factorize` over lexicographically sorted `||`-joined key strings), deterministic and identical for Experiments A and B. `GroupShuffleSplit` puts exactly 22 of 106 groups in the holdout; `GroupKFold(5)` validates within the 84 training groups so each training group is held out exactly once. Holdout data is never used for tuning or model selection, and is evaluated exactly once.

Split summary:

| Set | Groups | Observations | Share of rows |
|---|---|---|---|
| Training | 84 | 1,188 | ~79.04% |
| Holdout | 22 | 315 | ~20.96% |
| Total | 106 | 1,503 | 100.0% |

## 9. Cross-validation and holdout results

Frozen metrics recorded in `models/model_metadata.json` and `reports/holdout_evaluation.json`:

- Mean GroupKFold CV MAE: 1.8947 (std 0.3294); CV RMSE 2.6272 (std 0.5015); CV R² 0.8556 (std 0.0422)
- Holdout (evaluated once): MAE 2.0673 dB, RMSE 3.1444 dB, R² 0.7702 (315 observations / 22 groups)
- Honest generalization gap (CV R² 0.856 → holdout R² 0.770), consistent with out-of-sample evaluation; holdout metrics frozen and never retuned.

## 10. Permutation importance findings

`sklearn.inspection.permutation_importance` (scoring `neg_mean_absolute_error`, `n_repeats=30`, `random_state=42`) on the holdout set — model behaviour, not physical causality:

| Rank | Feature | Δ MAE (dB) | Std (dB) |
|---|---|---|---|
| 1 | `log10_frequency_hz` | 4.890 | 0.262 |
| 2 | `chord_length_m` | 3.092 | 0.193 |
| 3 | `angle_of_attack_deg` | 2.600 | 0.157 |
| 4 | `suction_side_displacement_thickness_m` | 2.523 | 0.151 |
| 5 | `free_stream_velocity_m_s` | 0.655 | 0.081 |

log10 frequency is by far the most influential feature; free-stream velocity the least. Narrow standard errors make the ranking stable across repeats (`reports/permutation_feature_importance.csv`, `reports/figures/permutation_feature_importance.png`).

## 11. Residual analysis

Holdout residuals (actual − predicted) scatter around zero across the full 200–20,000 Hz range with no systematic frequency-dependent drift (`reports/figures/residuals_by_frequency.png`). Per operating configuration (`reports/residuals_by_operating_group.csv`): worst group id 55 (α=22.2°, chord 0.0254 m, V=71.3 m/s, thickness 0.0214 m, n=15) has all-positive residuals, mean +8.48 dB, max |error| 21.82 dB — under-prediction of one configuration, not global bias. Group means split roughly evenly between under- and over-prediction. Small groups (n=11–17) make per-group means noisy; treat as descriptive only. Full interpretation and limitations in `reports/residual_analysis.md`.

## 12. Technical architecture

```
app/streamlit_app.py        # Phase 12 frontend: 5 bounded inputs, Predict button, dB result
src/airfoil_noise/
  config.py                 # schema, FEATURE_BOUNDS, feature lists, row-count contract
  data.py                   # raw .dat ingestion + processed CSV
  validation.py             # schema/quality checks
  features.py               # Experiment A / Experiment B frames (log10 frequency)
  groups.py                 # operating group ids + group-aware splitting
  holdout.py                # Phase 8 single-pass holdout evaluation
  models.py                 # Phase 7 five-model GroupKFold comparison
  explainability.py         # Phase 9 permutation importance + residual plots
  predict.py                # Phase 11 backend: load_model, validate, predict
  artifact.py               # Phase 10: fit, stage, verify, promote frozen artifact
models/best_model.joblib    # fitted pipeline (raw 5 features in; log10 inside)
models/model_metadata.json  # DOI, metrics, hyperparameters, package versions
reports/                    # comparison CSVs, holdout predictions, figures, analyses
tests/                      # 78 tests, all phases
notebooks/                  # 01_data_understanding, 02_exploratory_analysis
```

Data flow: user input → Streamlit widgets bounded by `config.FEATURE_BOUNDS` → `predict.validate_prediction_input` → `predict.load_model` (metadata-compatible SVR pipeline) → one-row DataFrame in `FEATURE_COLUMNS` order → pipeline computes `log10(frequency_hz)` internally → `StandardScaler` → `SVR(RBF)` → finite float → `"{:.2f} dB"`. The app never loads joblib directly and never duplicates input bounds.

## 17. Limitations and reproducibility

**Limitations**
- Single frozen holdout (315 rows / 22 operating groups); results are specific to the `random_state=42` GroupShuffleSplit draw.
- Valid only within the observed input envelope (bounds in Section 3); extrapolation outside is blocked by widget and backend validation.
- Small holdout groups (n=11–17) make per-group residual means noisy.
- Permutation importance and residual patterns describe model behaviour on held-out data — not physical causes of airfoil noise; no causal claims are made.
- No Release 2.0 functionality (no history, export, uploads, accounts, API, database, cloud).

**Reproducibility**
1. Clone the repo; raw `.dat` is the immutable source (hash pinned in `tests/test_holdout.py`).
2. Create the venv, install `pip install -e .`, run `streamlit run app/streamlit_app.py`.
3. Regenerate the artifact with `python src/airfoil_noise/artifact.py` (deterministic given frozen data, groups, seed 42, and recorded hyperparameters).
4. Run the suite: `pytest -q` (78 tests, all passing; set `OPENBLAS_NUM_THREADS=1`, `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `MPLBACKEND=Agg` for stable matplotlib/threading behaviour).
5. Regenerated reports/figures match the committed ones; holdout CSV and metrics are frozen and never retuned.

Package versions at artifact creation: Python 3.14.3, numpy 2.5.5, pandas 3.1.1, scikit-learn 1.9.1, joblib 1.6.0.
